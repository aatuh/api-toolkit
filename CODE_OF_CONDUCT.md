# Code of Conduct

## Purpose

api-toolkit is a small open-source Go project. Contributions, issues, reviews,
and security reports should stay focused, respectful, and useful for people
trying to build reliable HTTP APIs.

## Scope

This policy applies to project spaces controlled by the maintainers, including:

- GitHub issues, pull requests, discussions, reviews, and comments,
- security advisory collaboration,
- project documentation and examples,
- maintainer-run chats or calls when they are explicitly about this project.

## Expected Behavior

- Be direct, technical, and respectful.
- Assume public comments may be read by new adopters and contributors.
- Keep criticism focused on code, documentation, behavior, evidence, or process.
- Disclose conflicts of interest when recommending dependencies, providers, or
  architectural direction.
- Report security issues privately through `SECURITY.md`, not public issues.

## Unacceptable Behavior

- Harassment, threats, insults, or discriminatory language.
- Sexualized comments or unwelcome personal attention.
- Publishing private contact details, credentials, tokens, secrets, or private
  vulnerability details.
- Repeated off-topic comments after a maintainer asks for focus.
- Bad-faith disruption of issues, reviews, release work, or security response.

## Reporting

For conduct problems in public project spaces, contact the maintainer through a
private GitHub message path when available, or open a minimal issue asking for a
private contact route without including sensitive details.

For security issues, use the private vulnerability reporting process in
`SECURITY.md`.

## Maintainer Actions

Maintainers may remove comments, edit issue titles for safety, ask participants
to pause, lock threads, close issues, block accounts from project spaces, or
escalate to GitHub moderation when behavior prevents productive project work.

Reports are handled best effort by the current single maintainer. Serious
security reports still follow the response targets in `SECURITY.md`.
