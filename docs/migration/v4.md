# Migrating To V4

V4 is a major module transition. Update core imports from
`github.com/aatuh/api-toolkit/v3/...` to
`github.com/aatuh/api-toolkit/v4/...`, and contrib imports from
`github.com/aatuh/api-toolkit/contrib/v3/...` to
`github.com/aatuh/api-toolkit/contrib/v4/...`.

The root `ports` package now contains only generic `Logger`, `Clock`, `IDGen`,
`NopLogger`, and `SystemClock`. Replace removed root-port imports as follows.

| V3 root port family | V4 replacement |
| --- | --- |
| Health checks, results, configuration, and managers | `endpoints/health` |
| Documentation providers, metadata, configuration, and paths | `endpoints/docs`; registry documentation metadata is `specs.DocumentationInfo` |
| Version metadata | `endpoints/version.Info` |
| Authorization and policy contracts | `authorization` |
| Idempotency records, stores, and reservation release | `middleware/idempotency` |
| Rate-limit contract | `middleware/ratelimit.Limiter` for existing adapters; `middleware/ratelimit.DecisionLimiter` for complete shared-store quota decisions |
| Resource-not-found sentinel | `httpx.ErrResourceMissing` |
| Router, middleware, CORS, environment, database, transaction, migration, validator, and outbound-client contracts | `github.com/aatuh/api-toolkit/contrib/v4/contracts` |

An application may define a narrower local interface instead of importing
`contrib/contracts`; it is intended for shared adapter and composition shapes,
not as a replacement generic root API.

JWT/JWK middleware and OAuth2 helpers now belong to the optional contrib
module. Update these imports mechanically:

| V3 root import | V4 import |
| --- | --- |
| `github.com/aatuh/api-toolkit/v3/middleware/auth/jwt` | `github.com/aatuh/api-toolkit/contrib/v4/middleware/auth/jwt` |
| `github.com/aatuh/api-toolkit/v3/oauth2` | `github.com/aatuh/api-toolkit/contrib/v4/oauth2` |

The validation behavior is unchanged: configure issuer, audience, allowed
algorithms, and JWKS material; keep dangerous skip-header bypasses limited to
trusted proxies. The root v4 module has no JWT/JWK requirements, so applications that do not import contrib auth do not inherit those dependencies.

For repository development, use the checked-in `go.work` file so the root,
contrib, and reference-service modules resolve together. Published consumers
should use v4 module versions and do not need a workspace or replace directive.

## Required-field behavior and the future v5 default

V4 keeps the existing `binding` required-field defaults for compatibility. JSON
required fields use non-zero decoded values, query decoding rejects missing and
all-empty source values, and path decoding treats an empty resolver value as
missing. If an endpoint accepts an explicit `false`, `0`, empty collection, or
`null` JSON member, choose `binding.RequiredModePresent` in its decoder config.

Presence validates that the source supplied the field; it is not a non-null or
non-zero business rule. For JSON, `null` is present, a non-pointer scalar is
decoded to its Go zero value, and a pointer remains nil. For a path value,
provide `binding.PathConfig.HasParam` as well as `PathConfig.Param` when the
router can distinguish a present empty parameter from an absent one.

V5 is planned to make source presence the default. Before that major upgrade,
select the v4 mode explicitly in new endpoints and put non-zero or non-null
requirements in semantic application validation.

## Health-manager construction

New health-manager wiring should start with `health.DefaultConfig`, apply
application settings, and call `health.NewManager(config)`. The checked
constructor rejects invalid timeouts, invalid cache duration when caching is
enabled, blank or duplicate probe names, and empty liveness or readiness probe
configuration. Add dependencies through `manager.RegisterCheckerChecked`,
which rejects nil, blank-name, and duplicate checkers instead of replacing an
existing checker.

`NewManagerWithConfig` and `NewWithConfig` are retained as deprecated v4
compatibility wrappers for existing callers. Migrate them during v4; v5 will
retain the validated concrete-manager construction path only. For deterministic
cache tests, set `Config.Clock`. A checker that ignores context cancellation
cannot be forcibly stopped; the manager returns an unhealthy timeout result,
and the checker must eventually return on its own.

## Chi Client IP Middleware

`contrib/adapters/chi.Middleware.RealIP()` is now safe for direct connections:
it ignores client-supplied forwarding headers, preserves `http.Request.RemoteAddr`,
and records the direct peer address for `middleware.GetClientIP(r.Context())`.

For reverse-proxy deployments, replace reliance on `RemoteAddr` with
`middleware.GetClientIP(r.Context())` and explicitly configure trusted proxy
CIDRs:

```go
router.Use(chi.ClientIPFromXFF("192.0.2.0/24", "2001:db8:1234::/48"))
```

Do not trust `X-Forwarded-For`, `X-Real-IP`, or `True-Client-IP` without a
proxy boundary that overwrites those headers and a matching CIDR configuration.

The retained root contracts and their consumers are verified in
[the V4 port ledger](../ports-v4-migration-ledger.tsv). Release validation uses
`make release-check API_BASE_REF=v3.1.2`; the API comparison recognizes the
intentional v3-to-v4 module-path change and does not attempt a same-module API
diff across the major boundary.
