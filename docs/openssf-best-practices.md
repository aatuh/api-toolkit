# OpenSSF Best Practices Gap Review

Audience: maintainers deciding whether api-toolkit can publish an OpenSSF Best
Practices Badge or OpenSSF Baseline badge.

The OpenSSF Best Practices Badge is a voluntary self-certification program at
https://www.bestpractices.dev. The site supports OpenSSF Baseline levels such as
baseline-1 and the larger metal series: passing, silver, and gold.

Current status: not claimed. api-toolkit does not yet publish an official badge
because the repository does not have a tracked bestpractices.dev project ID and
the remaining criteria below still need maintainer confirmation or follow-up
tickets. Do not add an official badge to the README until the project is
registered, the relevant criteria are answered on the Best Practices site, and
the badge URL points to that project ID.

## Current Evidence

Open gaps: branch protection, MFA, dependency review, license policy,
maintainer availability, and CODE_OF_CONDUCT.

| Area | Status | Evidence or gap |
| --- | --- | --- |

## Claiming Rule

Do not add an official badge until all of these are true:

1. The project has a registered bestpractices.dev project ID.
2. The selected baseline or metal-series criteria are completed on the site.
3. External repository settings needed by the criteria, including branch
   protection and MFA evidence, have been checked by a maintainer.
4. Remaining local gaps in this document are resolved or recorded as accepted
   non-applicable answers on the Best Practices site.
5. `GOTOOLCHAIN=local make docs-check` passes after adding the badge.

When those conditions are true, add the official Markdown badge generated by
the Best Practices site and update this document from gap review to claimed
badge evidence.
