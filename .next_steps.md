# Next Steps: Finish and Prove v3.1.0

This file tracks the remaining release-and-proof work for the next api-toolkit
v3 release. It replaces the older v3.0.1/v3.0.0 guidance. Use `v3.1.0` as the
next release because the validate v3 adapter migration is source-compatible but
behavior-significant for a supported contrib adapter. Use `v3.0.2` as the API
and contrib release baseline until `v3.1.0` is published.

## 1. Release readiness from current master

- [ ] Confirm `git status --short --branch` is clean.
- [ ] Run `GOWORK=off GOTOOLCHAIN=local make github-governance-check`.
- [ ] Run `API_BASE_REF=v3.0.2 GOWORK=off GOTOOLCHAIN=local make release-check`.
- [ ] Run `API_BASE_REF=v3.0.2 GOWORK=off GOTOOLCHAIN=local make release-evidence`.
- [ ] Run `RELEASE_SUMMARY=release-check-summary.json make release-review-summary`.
- [ ] Confirm `release-check-summary.json` is `status=passed`,
  `publication_eligible=true`, has no failed checks, and records the current
  commit.

## 2. Generated scaffold evidence

- [ ] Run the manual `generated-full-integration` workflow with
  `include-minio=false`.
- [ ] Run the manual `generated-full-integration` workflow with
  `include-minio=true`, or wait for a scheduled MinIO run before claiming object
  storage integration evidence.
- [ ] If local Docker evidence is needed, run
  `GOWORK=off GOTOOLCHAIN=local make generated-integration-check`.
- [ ] If local MinIO evidence is needed, run
  `GOWORK=off GOTOOLCHAIN=local make generated-integration-check-minio`.
- [ ] Record the successful workflow URLs or local status in the release review
  notes. These checks remain outside default `make finalize`.

## 3. Generated upgrade compatibility

- [ ] Run `GOWORK=off GOTOOLCHAIN=local make generated-upgrade-compat-check`.
- [ ] Record the result in release review notes.
- [ ] Keep this as opt-in release evidence, not a default local finalize gate.

## 4. Cut and verify v3.1.0

- [ ] Create tag `v3.1.0` on the exact commit that passed release readiness.
- [ ] Push `v3.1.0` and let `.github/workflows/release.yml` regenerate clean
  publication evidence on the tag commit.
- [ ] Confirm the draft release contains `release-check-summary.json`,
  `release-evidence-logs.tgz`, SBOMs, signatures, certificates, checksums,
  manifest, and provenance attestations.
- [ ] Download draft assets to `.ci-result/release-assets/v3.1.0`.
- [ ] Run
  `RELEASE_ASSET_DIR=.ci-result/release-assets/v3.1.0 RELEASE_ARTIFACT_VERIFY_MODE=publication RELEASE_TAG=v3.1.0 GITHUB_REPOSITORY=aatuh/api-toolkit make release-artifact-verify`.
- [ ] Publish only after governance, release workflow, generated integration
  evidence, artifact verification, and reviewer summary are clean.

## 5. Advance the v3 baseline after publishing

- [ ] Update release docs and workflow examples from `v3.0.2` to `v3.1.0`.
- [ ] Run `GOWORK=off GOTOOLCHAIN=local make finalize`.
- [ ] Commit as `docs: advance v3 release baseline`.

## 6. Dependency PR triage

- [ ] Verify there are no stale Dependabot PRs already covered by local commits.
- [ ] Handle security/runtime updates first: JWT/JWKS, `x/crypto`, `x/net`,
  OpenTelemetry.
- [ ] Handle GitHub Actions runtime/release action updates second.
- [ ] Handle router, validator, scorecard, and lower-risk updates last.
- [ ] For each merged dependency PR, run focused tests plus `make coverage-check`,
  `make test-race`, `make vuln`, `make gosec`, and
  `API_BASE_REF=v3.1.0 GOTOOLCHAIN=local make contrib-api-drift-report`.

## 7. Coverage hardening backlog

- [ ] Add behavior tests before raising any floor.
- [ ] Prioritize JWT, health/readiness, pgxpool, OpenAPI validation middleware,
  `contrib/webhookdelivery`, and the Postgres webhookdelivery adapter.
- [ ] Raise floors only to observed post-test coverage.
- [ ] Keep `GOWORK=off GOTOOLCHAIN=local make coverage-check` green.

## 8. Reference adoption proof

- [ ] Add a separate reference service module at `examples/reference-saas-api`
  generated from `saas-api-full`.
- [ ] Keep it production-like: Postgres, Redis, API keys, tenant membership,
  idempotency, async operation, outbox/webhook delivery, audit, OpenAPI typed
  client, and admin metrics/health/pprof isolation.
- [ ] Add `make reference-service-check` to verify the reference service without
  adding it to default `make finalize`.
- [ ] Document its test, integration, migration, backup/restore, and load-smoke
  evidence.

## 9. Production feedback loop

- [ ] Use api-toolkit in one low-risk real service behind a conservative rollout.
- [ ] Track P0 issues for security, data loss, or cross-tenant behavior.
- [ ] Track P1 issues for idempotency, auth, runtime OpenAPI mismatch, or
  migration failure.
- [ ] Track P2 issues for scaffold ergonomics, docs gaps, or operational polish.
- [ ] Feed findings back into the next patch or minor release.
